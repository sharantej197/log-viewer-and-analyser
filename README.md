# LOG Viewer & Analyser

Flask application for validating supported Apache-style error logs, converting them to structured CSV, displaying records, filtering by timestamp, and generating charts.

## Features
- Upload and validate `.log` files (20 MB maximum).
- View structured records and download processed CSV.
- Generate four visualisations and download SVG/PNG/PDF output.
- Filter records by start and end date/time.
- Separate workspace per browser session; uploaded data and charts are not shared between visitors.

## Stack
Python 3.12, Flask, Gunicorn, NumPy, Pandas, Matplotlib, Bash, GNU AWK.

## Run locally (Linux, macOS, or WSL)
```bash
sudo apt-get update && sudo apt-get install -y bash gawk
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
export SECRET_KEY="replace-with-a-long-random-secret"
python website.py
```
Open http://127.0.0.1:5000.

## Deploy to Render
1. Push this project to a GitHub repository (do not include `.git`, uploaded logs, or generated charts).
2. In Render, create a **Blueprint** from the repository; it will read `render.yaml`.
3. Confirm the service has `SECRET_KEY` generated by Render and `COOKIE_SECURE=true`.
4. Deploy and test with two separate browser sessions to verify workspace isolation.

The app stores workspaces on the service filesystem. They are isolated by signed browser session and are ephemeral on platforms whose filesystem resets during redeploy/restart. For durable uploads or horizontal scaling, configure shared object storage and a shared session store before scaling beyond one service instance.

## Supported input format
The validator accepts lines matching this shape:
```text
[Mon Apr 07 10:15:30 2025] [error] Example Apache error message
```
The parser is tailored to selected Apache/mod_jk messages; it is not a universal Apache/Nginx parser.

## Security notes
- Submitted Python code is not executed; the old custom plotting endpoint was removed.
- Uploaded filenames are sanitized, uploads are size-limited, and CSV values are rendered with template auto-escaping.
- Each session has its own workspace and authenticated file-serving route.
- Set a stable, secret `SECRET_KEY` in production.
